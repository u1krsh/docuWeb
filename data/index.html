Data Layer Architecture Overview

Data Layer Responsibility
The Data Layer (src/gmfm_app/data/) abstracts all low-level persistence operations. It bridges in-memory domain models with local SQLite tables and manages field encryption, connection pooling, and synchronization transaction queueing.

2. The DatabaseContext Manager

Database connections are not opened as raw ad-hoc global objects. Instead, instances of DatabaseContext are passed via dependency injection to repositories and views:

gmfm_app/data/database.pyDatabaseContext Class
class DatabaseContext:
    def __init__(self, db_path: str | None = None, security: "SecurityProvider" | None = None):
        self.db_path = Path(db_path).expanduser() if db_path else None
        self.security = security

    def connect(self) -> Generator[sqlite3.Connection, None, None]:
        return db_context(self.db_path)

    def encrypt(self, value: Optional[str]) -> Optional[str]:
        if self.security:
            return self.security.encrypt(value)
        return value

    def decrypt(self, value: Optional[str]) -> Optional[str]:
        if self.security:
            return self.security.decrypt(value)
        return value

3. Dual-Validation Schema Architecture

To support desktop and mobile devices seamlessly, models in models.py use a conditional import pattern. On desktop machines where Pydantic and its compiled C-extensions are available, full type validation is enforced. On resource-constrained mobile devices where binary extensions may be disabled, the module automatically activates a pure-Python dataclass fallback with custom datetime and dictionary coercions.
