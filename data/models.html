Domain Models & Dual-Validation Pattern

This manual details the three core domain entities: Student, Session, and AppUser, along with the defensive dual-validation pattern that allows runtime execution across desktop and mobile devices.

Document Contents
  • 1. Student Entity (Patient Profile)
  • 2. Session Entity (Clinical Assessment)
  • 3. AppUser Entity (User Account)
  • 4. Dual-Validation Pattern Implementation

1. Student Entity (Patient Profile)

Represents the child receiving physical therapy or clinical motor evaluation:

raw_scoresDict[int, int]Keys: 1-88, Vals: 0-3Stored as a serialized JSON string in SQLite.

user_idOptional[int]Foreign Key → app_usersThe clinician who administered the test.

4. Dual-Validation Pattern Implementation

src/gmfm_app/data/models.pyDefensive Fallback Architecture
try:
    from pydantic import BaseModel, Field, constr, conint

    class Student(BaseModel):
        id: Optional[int] = None
        given_name: constr(min_length=1)
        family_name: constr(min_length=1)
        dob: Optional[date] = None
        identifier: Optional[str] = None
        user_id: Optional[int] = None
        created_at: datetime = Field(default_factory=datetime.utcnow)

    # [Session and AppUser models...]

except Exception:
    from dataclasses import dataclass, field

    @dataclass
    class Student:
        given_name: str = ""
        family_name: str = ""
        id: Optional[int] = None
        dob: Optional[date] = None
        identifier: Optional[str] = None
        user_id: Optional[int] = None
        created_at: datetime = field(default_factory=datetime.utcnow)

        def __post_init__(self):
            self.created_at = _parse_datetime(self.created_at)
            if self.dob is not None:
                self.dob = _parse_date(self.dob)
