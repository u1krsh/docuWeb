Schema Migration Engine (13 Idempotent Steps)

Zero-Downtime Local Migrations
MotorMeasure Pro maintains backward compatibility across software releases by executing an automated, idempotent in-code migration sequence inside src/gmfm_app/data/database.py:init_db() whenever a database connection opens.
Document Contents
  • 1. How In-Code Migrations Work
  • 2. The 13 Sequential Migration Steps
  • 3. One-Time Administrator Bootstrapping

1. How In-Code Migrations Work

Rather than requiring command-line migration tools (like Alembic) that are difficult to package and invoke inside mobile application sandbox runtimes, migrations are structured as safe ALTER TABLE and CREATE TABLE IF NOT EXISTS statements. Each statement is wrapped in defensive try/except sqlite3.OperationalError blocks, guaranteeing that re-running init_db() is completely idempotent.

2. The 13 Sequential Migration Steps

Step # Migration Operation Underlying SQL Statement Evolutionary Purpose
1 Rename patients → students ALTER TABLE patients RENAME TO students Replaces clinical institutional phrasing with inclusive educational terminology.
2 Add sessions.notes ALTER TABLE sessions ADD COLUMN notes TEXT Introduces free-form qualitative assessment observations.
3 Add app_users.role ALTER TABLE app_users ADD COLUMN role TEXT DEFAULT 'clinician' Establishes role-based access foundation.
4 Add app_users.is_active ALTER TABLE app_users ADD COLUMN is_active INTEGER DEFAULT 1 Enables soft deactivation of retired clinician accounts.
5 Rename patient_id → student_id ALTER TABLE sessions RENAME COLUMN patient_id TO student_id Synchronizes foreign key column naming with the renamed table.
6 Add app_users.email ALTER TABLE app_users ADD COLUMN email TEXT DEFAULT '' Supports Supabase GoTrue cloud identity integration.
7 Add app_users.cloud_uid ALTER TABLE app_users ADD COLUMN cloud_uid TEXT DEFAULT '' Binds local SQLite user rows to remote PostgreSQL UUIDs.
8 Add students.user_id ALTER TABLE students ADD COLUMN user_id INTEGER DEFAULT 1 Introduces per-user data isolation for student ownership.
9 Add sessions.user_id ALTER TABLE sessions ADD COLUMN user_id INTEGER DEFAULT 1 Records authoring clinician identity on every assessment session.
10 Rename role clinician → teacher UPDATE app_users SET role = 'teacher' WHERE role = 'clinician' Standardizes nomenclature across UI and access services.
11 Create student_access table CREATE TABLE IF NOT EXISTS student_access (...) Establishes unified relationship graph for co-teachers, parents, and sponsors.
12 Backfill owner access links INSERT OR IGNORE INTO student_access ... SELECT id, user_id, 'owner' FROM students Idempotently populates relationship table for all pre-existing student records.
13 Bootstrap first administrator UPDATE app_users SET role = 'admin' WHERE id = (SELECT id FROM app_users ORDER BY created_at ASC LIMIT 1) Promotes the earliest registered account to administrator if no admin exists.

3. One-Time Administrator Bootstrapping

On a fresh system deployment, no accounts exist. When the initial user registers, AuthService detects that UserRepository.count_users() == 0 and automatically assigns the admin role. For legacy single-user databases upgrading to v0.0.3, Migration Step 13 automatically promotes the earliest created local account, ensuring administrative console access is never locked out.
