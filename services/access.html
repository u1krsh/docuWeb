Access Scoping & Role Isolation Service

Fail-Closed Scoping
AccessService (src/gmfm_app/services/access_service.py) enforces data authorization boundaries across local repositories. If access resolution encounters an error, it fails closed, returning an empty student set.
Document Contents
  • 1. User Role Definitions
  • 2. The AccessScope Dataclass
  • 3. Mathematical Scope Resolution

1. User Role Definitions

RoleStudent Data ScopeWrite PermittedAdmin Console
admin Unrestricted (sees all local students) Yes Yes (Full user management)
teacher Owned students ∪ Co-taught shared students Yes No
parent Only explicitly linked children (via student_access) No (Strictly Read-Only) No
sponsor Aggregate clinical statistics only No (Strictly Read-Only) No

2. The AccessScope Dataclass

src/gmfm_app/services/access_service.pyAccessScope Contract
@dataclass
class AccessScope:
    user_id: Optional[int]
    visible_ids: Optional[Set[int]]  # Set of permitted IDs (None = unrestricted)
    can_write: bool                  # Gating flag for mutations
    is_admin: bool                   # Admin privileges
    role: str                        # Active role string
    unrestricted: bool = False       # True only for admin

3. Mathematical Scope Resolution

For a non-admin user with ID \( u \), the set of visible student identifiers \( V_u \) is formulated as:

SQL Scope QueryUnion Operation
SELECT id FROM students WHERE user_id = :uid
UNION
SELECT student_id FROM student_access WHERE user_id = :uid;

This single SQL query resolves both direct ownership and delegated co-teaching or parental visibility in \( O(1) \) database time.
