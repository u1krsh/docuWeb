System Architecture Overview

Architecture Summary
MotorMeasure Pro is engineered using a decoupled, 4-tier layered architecture: Presentation (Views), Business Logic (Services), Data Access & Persistence (Data), and Clinical Engine (Scoring). The system isolates platform dependencies and networking, ensuring offline reliability.

1. Core Architectural Tenets

Offline-First Autonomy
The local SQLite database is the immediate source of truth for all clinical transactions. The app performs zero mandatory network calls on startup, during student profile editing, or while scoring an 88-item assessment.
Stateless Clinical Scoring
The scoring engine (gmfm_app.scoring.engine) is a pure, side-effect-free mathematical function. It accepts raw inputs, applies validation and clamping, and computes domain and total percentages without coupling to the UI or database.
Defensive Execution & Graceful Degradation
Every optional third-party module (Pydantic, cryptography, ReportLab, fpdf2, Supabase) is imported defensively. If platform constraints disable compiled binary libraries on mobile, the system falls back to pure Python implementations without halting.
Git-like Asynchronous Synchronization
Local mutations write an audit log into an internal sync_queue table. A decoupled background thread (SyncWorker) evaluates network availability and negotiates bidirectional synchronization with Supabase when online.

3. Package & Directory Organization

The code repository is structured under src/gmfm_app with explicit modular boundaries:

Directory / Module Lines of Code Architectural Responsibility
gmfm_app/main.py 712 App entry point, animated splash screen, views-based routing controller, theme manager.
gmfm_app/data/ ~860 Database connection manager, automated migrations, domain models, and CRUD repositories.
gmfm_app/scoring/ ~380 Canonical GMFM-88 items catalog (JSON), lazy constants, and domain mathematical engine.
gmfm_app/services/ ~2,750 Authentication, cloud sync, background worker, PDF reporting, role access, and device APIs.
gmfm_app/views/ ~3,600 Flet interactive screen components, form validators, dialogs, and navigation triggers.
tests/ ~400 Unit test suite for scoring boundary verification and DOCX assessment document parsing.

4. Runtime Adaptation & Entry Points

MotorMeasure Pro provides multiple specialized entry points depending on target runtime:

  • src/gmfm_app/main.py: The master entry function main(page: ft.Page). Detects desktop vs mobile runtimes. On desktop, initiates a multi-stage animated brand splash screen while building the database on a worker thread.
  • src/main.py: Standard wrapper imported by Flet's packaging build tools during Android APK compilation.
  • src/entry_point.py: Minimal bootloader configured for Serious Python Android embedder.
  • src/gmfm_app/main_desktop.py: Dedicated standalone launcher for desktop debugging without packaging dependencies.
